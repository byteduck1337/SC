# 🛡️ Цифровой Щит — локальный аудит безопасности браузера

> Образовательный веб-проект, который за ~10 секунд оценивает уязвимость вашего браузера
> по **15 векторам атак** и выдаёт результат в процентах вместе с персональным планом защиты.

## 📌 О проекте

**Цифровой Щит** — это одностраничное приложение без бэкенда, которое проверяет,
насколько браузер и текущая страница пользователя уязвимы к реальным типам атак:
от эксплойтов движка и криптоджекинга до фишинга и сбора цифрового отпечатка.

Сканирование запускается **только после явного согласия пользователя** и выполняется
полностью локально — ни один байт данных не покидает устройство.

### Ключевые принципы

| Принцип | Реализация |
|---|---|
| 🔒 **Информированное согласие** | Модальное окно с чекбоксом — кнопка запуска неактивна без подтверждения |
| 🖥️ **Полная локальность** | Все проверки выполняются в браузере, сервер не участвует |
| 📊 **Прозрачность** | Живая консоль показывает каждую проверку в момент выполнения |
| 🎯 **Практичность** | Каждая найденная проблема сопровождается рекомендацией со ссылкой на источник |

## 🔍 Что проверяется (15 угроз)

| # | Угроза | Что анализируется |
|---|--------|-------------------|
| 1 | **Drive-by Download** | Скрытые iframe, ссылки на исполняемые файлы (.exe, .msi, .apk), meta-refresh |
| 2 | **Эксплойты браузера** | Актуальность версии Chrome / Edge / Firefox / Safari, тип движка (Blink, Gecko, WebKit), GPU |
| 3 | **Эксплойты плагинов** | Остатки Flash / Java / ActiveX, элементы `<object>`, `<embed>`, `<applet>` |
| 4 | **XSS** | Небезопасные параметры URL, наличие заголовка CSP, объём inline-скриптов |
| 5 | **CSRF** | POST-формы без токенов, изменяющие операции через GET |
| 6 | **Кликджекинг** | Заголовки X-Frame-Options / CSP frame-ancestors, открытие страницы во фрейме |
| 7 | **Фишинг** | Эвристики URL: IP вместо домена, Punycode, «приманочные» слова, избыток поддоменов |
| 8 | **Спуфинг** | HTTPS, mixed-content, наличие HSTS |
| 9 | **Session Hijacking** | Доступные из JS cookies, secure context, шифрование канала |
| 10 | **Fingerprinting** | Canvas-отпечаток, User-Agent, экран, CPU/RAM, Do Not Track |
| 11 | **Криптоджекинг** | Сигнатуры известных майнеров (Coinhive, CryptoLoot и др.), WASM-модули |
| 12 | **Атака «Водопой»** | Сторонние скрипты, подозрительные доменные зоны, скрипты по HTTP |
| 13 | **Scareware** | Пугающая лексика на странице, агрессивные фиксированные баннеры |
| 14 | **Брутфорс** | Формы ввода пароля без капчи / антибота |
| 15 | **Ботнет** | Выданные разрешения (уведомления, геолокация), зарегистрированные Service Workers |

## ⚙️ Как это работает
Кнопка «Начать проверку»
        │
        ▼
Модальное окно согласия ──✕── Отмена
        │ ✓
        ▼
Живая консоль аудита: 15 последовательных проверок с прогресс-баром
        │
        ▼
Отчёт: процент уязвимости + вердикт + 15 карточек + рекомендации


### Сценарий пользователя

1. Пользователь нажимает **«Начать проверку»**.
2. Открывается окно согласия с описанием того, что именно будет проверяться.
3. Движок последовательно выполняет 15 проверок, логируя каждую в терминал.
4. По каждой проверке вычисляется уровень риска (0–100 %).
5. Пользователь получает итоговый отчёт.

### Формула оценки
риск_проверки      = 100 − safety
уязвимость (%)     = Σ(риск × вес) / Σ(вес)

Критичные векторы (эксплойты браузера, фишинг, кража сессии) имеют повышенный вес.

| safety проверки | Статус |
|---|---|
| ≥ 80 | 🟢 Низкий риск |
| 50–79 | 🟡 Средний риск |
| < 50 | 🔴 Высокий риск |

Итоговый вердикт имеет 5 уровней — от «Минимальный уровень уязвимости» до «Критический уровень уязвимости», шкала меняет цвет от зелёного к красному.

## 🧰 Технологии

- **HTML5 / CSS3 / Vanilla JavaScript (ES2022+)** — без фреймворков, сборщиков и зависимостей.
- **Дизайн-стандарты 2026**: тёмная тема, glassmorphism (`backdrop-filter`), bento-сетки, неоновые акценты, микроанимации.
- **SVG-иконки вместо эмодзи** — единый спрайт в JS + inline-SVG в разметке.
- **Шрифты**: Manrope (интерфейс) + JetBrains Mono (консоль аудита).
- CSS-переменные, `IntersectionObserver` (reveal-анимации), поддержка `prefers-reduced-motion`, адаптив до 360 px.

## 🧠 Архитектура кода (`script.js`)

| Блок | Назначение |
|---|---|
| `ICONS` + `icon()` | Библиотека SVG-иконок и хелпер рендера |
| `THREATS` | Данные для энциклопедии из 15 угроз |
| `RECS` | База рекомендаций с внешними ссылками (MDN, OWASP, EFF, Kaspersky) |
| `checkDriveBy()` … `checkBotnet()` | 15 асинхронных функций проверок; каждая возвращает `{ safety, findings }` |
| `CHECKS` | Реестр проверок с весами для итоговой формулы |
| `runAudit()` | Оркестратор: HEAD-запрос заголовков → последовательные проверки → живой лог |
| `renderResults()` | Анимированная SVG-шкала (gauge), вердикт, раскрывающиеся карточки проверок |
| `renderRecommendations()` | Генерация плана действий, отсортированного по приоритету |

### Ключевые технические детали

- **Заголовки безопасности** (CSP, HSTS, X-Frame-Options) получаются через `fetch(HEAD)`
  к текущей странице; при CORS-ограничениях или запуске через `file://` движок
  автоматически переходит в режим частичной проверки и помечает это в логе.
- **Canvas-отпечаток** вычисляется реально: рисуется тестовый градиент с текстом,
  хеш `toDataURL()` демонстрирует уникальность браузера.
- **Разрешения** (уведомления, геолокация) запрашиваются через `navigator.permissions.query()`
  с безопасным fallback, если API недоступен.
- **Scareware-детектор** исключает собственные секции сайта (`[data-no-scan]`),
  чтобы тексты энциклопедии угроз не давали ложных срабатываний.

📊 Что получает пользователь

    Круговая шкала с процентом уязвимости и цветовым вердиктом (5 уровней);
    Счётчики: сколько проверок в порядке / требуют внимания / критичны;
    15 раскрывающихся карточек — по клику видна шкала риска и список конкретных находок;
    Персональный план защиты с приоритетами «Критично → Важно → Рекомендуется»
    и ссылками на авторитетные источники (MDN, OWASP, EFF, Kaspersky).

⚠️ Дисклеймер
Проект создан исключительно в образовательных целях для повышения киберграмотности.
Это эвристический клиентский аудит, а не профессиональное тестирование на проникновение.
Результаты отражают состояние браузера и текущей страницы в момент проверки
и не дают 100 % гарантии безопасности.
Все проверки выполняются на стороне клиента. Данные не передаются на сервер.
